## v0 — Repo bootstrap + design foundation
**Goal:** The repo can be pushed to GitHub: it runs, its rules are documented,
and its design/art tooling is scaffolded.
**Milestone criteria** (ship when all are ✅):
- [x] Split layout (Q-003 ✅): `index.html` + `styles/` + `scripts/` (ES modules) renders an empty scene in a browser.
- [ ] Repo-level `AGENTS.md` present (repo rules for AI agents, pointing to design docs).
- [x] `docs/design/rabbit-game/` complete: PRD, QUESTIONS, ROADMAP, IDEAS, AGENTS, HANDOFF.
- [x] Art design docs scaffolded: `art/ART-BIBLE.md`, `art/style-lock.yaml` (stub), `art/ART-SETUP.md`, `art/adrs/*`, `SHOTKIT/input-brief.md` seeded.
- [x] Art style decided (Q-002 ✅): smooth kawaii illustration → ART-BIBLE §2 rewritten, style_flags set.
- [ ] `references/` and `prototypes/` folders in use (references/ started; prototypes/ empty until first exploration).
- [ ] `git init` + first commit made; `.gitignore` sensible (no secrets, round PNG policy decided later).
**In scope:** docs, skeleton page, tooling scripts stubs.
**Out of scope:** any final art/audio.

## v0.1 — Playable toy (placeholder art/sound)
**Goal:** A person on a phone or laptop can feed the rabbit and pet it, and the
rabbit animates and makes cute noises — all with deliberately temporary
placeholder sprites and synthesized sounds.
**Dependencies:** v0 milestone met (Q-003 resolved ✅ · 2026-10-23).
**Milestone criteria** (ship when all are ✅):
- [ ] Pet gesture (pointer stroke on rabbit) triggers happy/wiggle animation.
- [ ] Feed affordance (drag or tap carrot) triggers eating animation + fed counter.
- [ ] At least two distinct cute noises (eating, content) via WebAudio; mute toggle persists.
- [ ] Idle loop with at least breathing + occasional blink.
- [ ] Input works identically with mouse and touch (Pointer Events).
- [ ] Core modules exercised by light tests (see Q-008) and manage self-playability at 390×844 and 1280×800.
- [ ] MANUAL PASS: Playwright smoke suite passes locally (webapp-testing skill).
**In scope:** RabbitState FSM, Input classifier, Renderer, Sound synth, Store, all placeholders clearly labeled `placeholder/`.

**Out of scope:** any pipeline-generated (final) art; name input; reduced-motion polish beyond basic honor ligt.

## v0.2 — Art + audio production via pipeline
**Goal:** Replace placeholders with pipeline-produced, accepted assets: a
brand-locked rabbit + carrot sprite set, and (if chosen) SFX samples preserved through provenance.
**Dependencies:** v0.1 milestone criteria ✅; Q-002 (style) answered; Q-011 (model pin) answered.
**Milestone criteria:**
- [ ] `SHOTKIT/` phase complete: `input-brief.md` finalized, reference research recorded, `brand-lock.md`, `style-lock.yaml` published.
- [ ] Calibration round for scale/guides recorded under `art/calibration/`.
- [ ] Asset specs (`art/specs/*.yaml`) for: rabbit idle/eating/happy sheets, carrot prop, scene/canvas dressing, favicon.
- [ ] Generation rounds + critiques executed per ADR-0001/0002; winning rounds accepted with full provenance; validation script passes `--all`.
- [ ] Assets promoted to `assets/` (spritesheet + manifest format from Q-012).
- [ ] Visual passes: sprite reads correctly at mobile scale; COMFORT TEST — is it cute?(subject-but-visible human sign-off criterion).
**Out of scope:** audio recording beyond the 3 planned SFX if synthesis chosen; seasonal themes.

## v1 — Published, polished, shareable
**Goal:** The toy is live on a public URL, looks designed end-to-end, and
survives first-contact with real phones.
**Dependencies:** v0.2 milestone criteria ✅; Q-009 (host) answered.
**Milestone criteria:**
- [ ] Deployed to GitHub Pages (or equivalent) [not started]; documented deploy steps in README.
- [ ] Real-device check: iOS Safari + Android Chrome interaction passes manual checklist.
- [ ] `prefers-reduced-motion` honored and tested.
- [ ] Payload < 5 MB; loks/works with devtools-cache disabled; zero console errors.
- [ ] README quickstart + screenshot; release tagged `v1.0.0`.

**Out of scope:** PWA manifest/service worker; account/sync of any kind.

## v2 — Affection features + PWA
**Goal:** Deepen the toy without drifting into sim: naming, more foods, moods, and installable/offline.
**Dependencies:** v1 shipped.
**Planned scope:**
- Optional name input + display (Q-007 resolution).
- Additional treats (blueberry? flower?) with reuse of pipeline per-asset pattern.
- PWA manifest + service worker (Q-010 resolution).
- More idle states, day-night tint.

## Backlog (Unversioned)

- Ambient sound (soft background loop) with autoplay handling.
- Multiple color variants of the rabbit via palette swap (see style-lock roles later).

---
## What Determines Version Boundaries
v0 = the repo is trustworthy (runs + documented). v0.1 = the toy is honestly
fun/working with placeholders. v0.2 = the aesthetic becomes product-grade via
the tracked pipeline. v1 = a stranger with a phone link can enjoy it. v2 =
affection depth features without expanding scope creep. Any feature that adds
network calls, accounts, or game mechanics (hunger/auth/game loops) is rejected
from all versions by the PRD Non-Goals unless the PRD itself is amended.
