## Interaction Delight
---
### IDEA-001 — Pet-quality scoring (pet *well*, and the rabbit melts)
**The idea:** Pet strokes in the right speed/direction feel "better" to the rabbit —
different noises and stronger wiggle — without any punishing negative feedback for "bad" pets.
**Why it's interesting:**
- Turns a gesture into a relationship; cheapest possible "depth" for the toy.
- Pure client input-classification maths won't add allowed frameworks.
**Why it's hard:**
- Tune curve without creating frustration; must read as cute, not judgmental.
**Research path:** Prototype stroke-velocity classifier in `prototypes/`; A/B two mood curves in v0.2 playtest.
---
### IDEA-002 — Onomatopoeia speech bubbles
**The idea:** Cute spatial text bubbles ("nib", "pprr", "boop") float out with
each noise — WebAudio sound + matching typographic visual.
**Why it's interesting:**
- Cute noises become visible so mute mode still communicates the rabbit's feelings.
- Shotkit text-overlays machinery (`text-overlays.json`) is already proven in the precursor for baked text; here we can run live DOM/CSS instead (no baked assets needed).
**Why it's hard:**
- Keeping the visual style consistent with final art (font choice is constrained by "no runtime CDN fonts").
**Research path:** Pick a single bundled display font (or pure-CSS letter shapes) in v0.1; bubble visuals re-skin in v0.2.
---

### IDEA-003 — WebAudio "animalese" synthesis
**The idea:** Synthesize rabbit noises as short formant-shaped oscillator chirps
(animal-food-style) with random pitch variation so the rabbit never sounds
mechanical.
**Why it's interesting:**
- Zero audio assets, infinite variation, matches "response to gestures" perfectly.
- Could later drive perfect lip-sync-ish mouth flap in the eating animation via shared event timing.
**Why it's hard:**
- Prototype-y synthesis can cross into annoying quickly — need volume envelope discipline and a cap on repeats within a cooldown window.
**Research path:** Sprint in `prototypes/`: generate 6 chirp shapes + envelopes; mute-friendly cooldown experiment.

## Affection Progression
---
### IDEA-004 — The carrot garden
**The idea:** Fed carrots occasionally "plant" a garden sprout in the
background scene — over days, the garden fills softly (persisted count).
**Why it's interesting:**
- Gentle persistence hook without sim demands; the rabbit stays need-free.
- Calm answer to "why keep the tab" mechanics.
**Why it's hard:**
- Calendar/day logic must be honest but casting (local Date; no offline drift handling complexities in v2).
- Garden art adds pipeline asset count.
**Research path:** Paper-prototype the state model in `prototypes/`; decide if art count for v2 fits budget.
---
### IDEA-005 — Camera-shy idle states
**The idea:** Rare idle behaviors — the rabbit stretches, flops on its side,
or "notices" the user and perks up when the cursor comes close.
**Why it's interesting:**
- Makes the toy feel observant and alive at near-zero interaction cost.
- Uses existing idle-loop machinery; no new input systems.
**Why it's hard:**
- More animation frames (pipeline spritesheet growth); timing rhythm needs taste.
**Research path:** Watch people's pet toys; shortlist 3 idle gestures; feed the list into v0.2 sprite spec only might match budget.

## Modes & Sharing
---
### IDEA-006 — Installable plushie (PWA home-screen pet)
**The idea:** Add a PWA manifest + service worker so a user can "install" the
rabbit as a home-screen icon that opens fully offline.
**Why it's interesting:**
- The toy earns a permanent spot on someone's phone — the strongest retention gesture available with zero account infrastructure.
**Why it's hard:**
- Service worker adds cache/versioning discipline (asset hash-busting), new failure modes.
**Research path:** Already safely re-claimed as v2 scope (Q-010 / ROADMAP v2). Prototype manifest-only variant in `prototypes/`.
---
### IDEA-007 — Palette-swap rabbit variants (calico/gray/black)
**The idea:** Same spritesheet recolored through style-lock color roles to offer a
(discreet) variant picker or daily-rabbit surprise.
**Why it's interesting:**
- Reuses every asset; palette-swap is a canvas-level operation.
- Cute personalization without any new content pipeline burden.
**Why it's hard:**
- Palette discipline in style-lock must index rabbit fur tones as discrete roles for swaps to stay clean.
**Research path:** Decide during brand-lock extraction: reserve fur-swap roles even if v1 ships single-variant.
---

### IDEA-008 — Synth character: pitch/gain variance on repeated noises (from threejs skills · game-feel)
**The idea:** Every repeated synth noise (munch, chirrup, soft blip) gets a small
per-play detune + gain jitter so spamming feeds never sounds machine-gunned; the
same-frame audio/visual sync stays (Feel rule #4, ADOPT-20261023).
**Why it's interesting:**
- One-line fixes per synth voice; huge felt-quality gain for the toy's main verbs.
**Why it's hard:**
- Careful not to detune the ambience bed (loop identity must hold).
**Landed in v0.2 (feel pass, 2026-10-23):** per-play detune + gain jitter in
`_blip`, crunch spacing jitter in `munch`; ambience bed untouched (loop identity held).
---
### IDEA-009 — Overshoot easing on hop + ghost return (from threejs skills · easeOutBack)
**The idea:** A 6-line overshoot curve (no tween library) for the happy hop and
the carrot ghost's return-to-basket — motion arrives with a tiny bounce.
**Why it's interesting:**
- Cheapest juice available; matches game-feel.md's "response curves" layer.
**Why it's hard:**
- Respect `prefers-reduced-motion` (no overshoot when reduced).
**Landed in v0.2 (feel pass, 2026-10-23):** damped-sine hop arc in `render.js`
(reduced-motion honored) + ghost return uses CSS `cubic-bezier(0.34, 1.56, 0.64, 1)`.
---
### IDEA-010 — Second version of the game in Three.js (sibling repo)
**The idea:** Port the toy to Three.js in a NEW sibling repo (constitution rule 1
bans frameworks here; this repo stays the vanilla artifact). Two scoped paths:
(1) billboard/2.5D port — sprite-plane rabbit with the promoted expression
frames, layered scene planes, camera parallax; ~1–2 sessions. (2) true-3D —
canon sprite via image-to-3D (Tripo, own paid-auth lane), auto-rig, orbit
camera; ~3–5 sessions, becomes a different product.
**Why it's interesting:**
- The expensive parts port as-is: FSM (`rabbit-state.js`, DOM-free), synth
  audio (`sound.js`), all promoted art + provenance, the design set/feel rules.
  Only the render layer + raycast input are new work.
- Buys depth/parallax/camera/lighting headroom (walking rabbit, more rooms).
**Why it's hard:**
- True 3D adds art-spend + rigging/animation; a pet toy is fundamentally
  2D-friendly, so the 3D version must earn its keep over the 2D one.
**Status:** parked at user direction 2026-10-24 ("not right now") — start with
the billboard path if revived.
---
### IDEA-011 — Godot 4 port (sibling repo; look into later at user direction)
**The idea:** Port the toy to Godot 4 with a web export (and iOS export later,
since the engine builds native iOS binaries directly). PNG assets import
natively as sprites; the precedent is `space-adventure-prototype` (Godot).
**Why it's interesting:**
- Full engine for free: scene tree, animation editor, UI system, and 3D built
  in — the "walking rabbit" future is native, no framework shopping.
- iOS/Android desktop exports from one codebase (stacks with the iOS goal).
**Why it's hard:**
- The WebAudio synth engine does NOT port (no WebAudio in Godot) — sounds must
  become generated WAV files via the art pipeline or Godot-native audio nodes.
- FSM + store rewrite in GDScript; web export is a WASM bundle and GitHub Pages
  hosting needs COOP/COEP headers for the threaded runtime.
**Status:** parked at user direction 2026-10-24 ("mark godot as an idea to look
into later") — the Capacitor WKWebView lane is the nearer iOS path.
