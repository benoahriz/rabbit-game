# rabbit-game — Agent Instructions

> **Last Updated:** 2026-10-25
> **Design Version:** v0.2 shipped; **v1 live** at https://rabbit.brainvault.xyz/

This document is the primary onboarding guide for any AI agent working on this system design.
Read this first before reading anything else.

---

## What This System Is

rabbit-game is a deliberately tiny virtual-pet toy that runs as a pure browser
page: **Casey**, an illustrated rabbit you can feed carrots and pet; she
responds with expression-frame animations (blink / ear twitch / chomp cycle /
happy joy) and cute synthesized noises — with speech bubbles as the mute
channel. No framework, no build step, no network at runtime, no accounts.
Cross-platform by construction (desktop + mobile browsers share a single code
path). Live at https://rabbit.brainvault.xyz/ (Cloudflare Workers static
assets, push-to-deploy); source public at github.com/benoahriz/rabbit-game.

The repo doubles as a proving ground for the agentic game-production pipeline
established in the sibling `space-adventure-prototype` repo: system-forge design
docs (in `docs/design/`), the SHOTKIT brand phase, and hybrid ComfyUI art
production with immutable generation rounds and provenance-tracked acceptance.

## Hard Constraints

These are non-negotiable:
- **Pure HTML/CSS/JS, no build step.** No frameworks, bundlers, package-installed runtime code, or TypeScript — ES modules and vanilla only.
- **Zero runtime network requests** beyond loading the page's own static files. No CDNs, no fetched fonts, no analytics, no telemetry.
- **Art provenance is sacred.** Final assets are produced ONLY via the tracked
  pipeline (generation rounds → critique → acceptance → promotion, recorded as
  hash-backedprovenance data). Never silently substitute hand-drawn, scraped, or AI-generated art outside the pipeline. Never mutate an existing round directory; revise by adding a new round.
- **Do not commit secrets** of any kind (the repo IS public on GitHub:
  github.com/benoahriz/rabbit-game).
- **`main` is production.** Every push to `main` auto-deploys
  https://rabbit.brainvault.xyz/ via Cloudflare Workers Git integration
  (~1 min; config in `wrangler.jsonc` + `.assetsignore`). Verify locally
  before pushing to main.
- **The `import/` lane is local-only** (user-supplied audio/source material,
  gitignored, rights-pending per Q-018). It is never committed, never deployed.
- **Respect non-goals.** No ad-earning game mechanics, no sim-style meters, no network features. If a request would violate PRD §8 Non-Goals, refuse/flag rather than implement.
- **Local-only tunnel bypass. Art generation orchestration runs through LeanCTX
  addon (`comfy-mcp`); paid-cloud generation requires explicit user instruction
  every time (`--allow-spend` interlock is never added to scripts).

## Design Principles

- **Proportionality.** This is a small toy; every technology decision must keep
  the artifact small. Prefer deletion over abstraction.
- **State-machine-first.** The rabbit is an explicit FSM with named states and
  transitions; behavior is data, not scattered conditionals.
- **Graceful degradation.** Missing audio/maps/input must fail closed and quiet,
  never in a broken UI.
- **Agent-operable repo.** Docs current, scripts deterministic, tests runnable
  headlessly, no magic steps.

---

## Do Not

- Do not add runtime dependencies (npm/CDN) of any kind. Dev-only tooling (e.g.,
  Playwright for tests) is acceptable if properly fenced.
- Do not resolve OPEN questions unilaterally — add entries to QUESTIONS and
  surface to the user.
- Do not mutate/draw final art assets manually (check ADR-0002 rules).
- Do not create new design doc types not present in this scaffold without need.
- Binary PNG policy (updated 2026-10-25, reflects actual practice): production
  round PNGs and promoted `assets/` ARE committed — the public repo IS the
  immutability evidence. User-supplied source material stays local-only per
  rights (`art/calibration/*/references/`, `import/` — both gitignored).
  README screenshots (`docs/screenshots/`) are documentation, not game art:
  exempt from the pipeline-provenance rule, still never hand-drawn game assets.

## When You're Unsure

Ask rather than assume. Surface uncertainty explicitly with "I'm not sure
whether X — should I...?". Do not guess on the art pipeline or provenance data;
better 30 minutes of questions than an AI-generated bad asset.

## Personality & Tone

System Architect persona (per system-forge). Concise, bullet-heavy. Direct about
tradeoffs; prefer "stop at the first level that solves it" (check repeated
patterns against existing repo machinery, stdlib, and browser platform before
inventing). Surface non-obvious risks — autoplay policies, TCC-protected
folder paths, viewport meta coverage — early.
