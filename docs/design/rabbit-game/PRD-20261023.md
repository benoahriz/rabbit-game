# rabbit-game — Product Requirements Document
> **Status:** Draft · v0.1 · 2026-10-23
> **Scope:** v1 — a single-page virtual pet toy: feed the rabbit carrots, pet it, hear cute noises, watch it animate. Pure HTML/CSS/JS in the browser. Desktop + mobile.
---
## 1. Overview
rabbit-game is a deliberately tiny, zero-install browser toy: an illustrated rabbit
living on a single web page. The player can **feed it carrots** and **pet it**
(stroking the rabbit); the rabbit responds with small, charming animations
(eating, happy wiggle/hop) and **cute noises**.
It exists for two reasons:
1. **The product reason:** a warm, low-stakes pet toy anyone can open on a phone
   or desktop — no install, no account, no network. A digital plushie.
2. **The systems reason:** a low-risk repo to prove out the full agentic game
   pipeline — system-forge design docs, the SHOTKIT brand phase, and the hybrid
   ComfyUI art pipeline — established in `space-adventure-prototype`, now targeting
   a pure-web runtime instead of Godot.
Complexity is the enemy. Every design decision must keep the playable artifact
small, dependency-free, and cross-platform.
---
## 2. Problem Statement
Most browser pet/toy pages today are ad-heavy flash relics, app-store games with
installs and monetization, or framework-built SPAs that ship megabytes for what is
essentially a sprite and a few sounds. There is no small, honest, free toy that
just opens and works.
Constraints we operate under:
- **No build step, no framework.** The artifact must remain readable vanilla HTML/CSS/JS.
- **Agents build and maintain it.** The repository is developed primarily by AI
  agents (OpenCode), so structure, docs, and tests must be agent-operable.
- **Art must be provenance-tracked.** All final assets are produced through the
  shotkit/ComfyUI pipeline with immutable rounds and recorded acceptance (never
  hand-drawn or silently substituted).
---
## 3. Use Cases
### UC-1: Feed the rabbit
Player drags (or taps) the carrot UI affordance onto the rabbit. Rabbit plays its
eating animation (chomp frames) and emits a happy eating noise. A counter or
subtle acknowledgment persists locally.
### UC-2: Pet the rabbit
Player strokes/pet-gestures directly on the rabbit. Rabbit reacts with a happy
wiggle/hop animation and a content noise. Rapid over-petting still reads as cute,
never punishing (no negative feedback in v1).
### UC-3: Idle watching
With no input, the rabbit sits with a gentle idle animation (breathing, blink,
ear twitch). Serves as "ambient cuteness" — the page is pleasant even untouched.
### UC-4: Sound on/off
Player can mute the toy. Mute state persists locally and is respected across
sessions.
---
## 4. Operating Modes
| Mode | Trigger | Input | Output |
|---|---|---|---|
| Feed action | carrot dragged onto rabbit / carrot button tap | pointer event (drag or tap) | eating animation + eating noise + fed counter |
| Pet action | stroke detected on rabbit | pointer move sequence (velocity-tracked swipe) | happy/wiggle animation + content noise |
| Idle | no interaction for N seconds | timer | idle loop animation, occasional blink/ear-twitch/tongue |
| Muted | mute toggle | click | suppresses all audio output; state persisted |

## 5. Architecture
### 5.1 Processing Pipeline
```
Browser (desktop or mobile)
   |
   v
index.html  (static page, no build, no framework)
   |
   ├─ Input layer (pointer events unified: mouse/touch/stylus; keyboard fallback)
   │     |  maps raw input to intents: FEED, PET
   │     v
   ├─ Rabbit state machine (idle | eating | happy ↑/↓, smoothing, timers)
   │     |  emits: animation frame index, one-shot animations, noise triggers
   │     ├──────────────> Renderer (Canvas 2D, spritesheet, viewport-fit scaling)
   │     ├──────────────> Sound engine (WebAudio: synthesized cute noises v1)
   │     └──────────────> Store (localStorage: fed-count, mute, minor prefs)
   v
UI overlay (DOM/CSS: title, carrot affordance, mute toggle)
```
### 5.2 Components
| Component | Responsibility | Technology |
|---|---|---|
| index.html + CSS | page shell, layout, overlay UI, responsive sizing | vanilla HTML/CSS |
| Renderer | draw background + rabbit sprites, scale to viewport, rAF loop | Canvas 2D, vanilla JS |
| RabbitState | FSM + timers for idle/eating/happy; animation frame selection | vanilla JS module |
| Input | pointer-event interpretation: pet-strokes vs taps vs drag-feed | vanilla JS (Pointer Events API) |
| Sound | synthesized cute noises (WebAudio oscillators/noise); mute gate | WebAudio API, no audio files in v1 |
| Store | persist fed count, mute flag | localStorage |
| Assets | spritesheet PNG + manifest, promoted from art pipeline | PNG promoted by art pipeline |
### 5.3 Processing Philosophy
- **Local-first, network-free at runtime.** The game makes zero network requests
  after the page loads; no CDNs, no fonts, no trackers.
- **Event-driven toy loop.** A single rAF loop drives rendering; state machine
  runs on events + simple timers. No ECS, no physics engine — not needed at this scope.
- **Audio requires a prior user gesture** (browser autoplay policy); first
  interaction toggles a one-time audio unlock. Fails closed, never errors aloud.
- **Graceful degradation.** Missing/failing audio must never break gameplay;
  `prefers-reduced-motion` slows/stops animation loops.

## 6. Input / Output
### 6.1 Inputs
- Pointer events (mouse, touch, stylus) via the unified Pointer Events API:
  swipe-stroke → pet; tap or drag of carrot affordance → feed.
- Keyboard fallback: `F` feeds, `P` pets (accessibility + desktop convenience).
- Browser hooks: visibility change (pause loop), page unload (nothing special).
### 6.2 Outputs
- Canvas-rendered animation frames (the only "visual surface").
- WebAudio-synthesized cute noises (eating munch, content chirrup, idle soft blink sound).
- localStorage record: `{ fed: <n>, muted: <bool>, nameOptional: <string|null> }`
---
## 7. Scope Boundaries
### In Scope
- One rabbit, one screen, carrot feeding, petting, idle loop.
- Cute noises via Web Audio synthesis (v1) — no recorded animal audio in v1.
- Responsive layout: comfortable on phones (375–430 px width) and desktop.
- Local persistence of mute state and simple counters.
- Full design-doc + art-pipeline tooling in `docs/design/`.
### Out of Scope — v1
- Games, timers, hunger/health meters (pet must never die or demand).
- Multiple pets, customization, backgrounds beyond one scene.
- Cloud features of any kind (accounts, analytics, remote saves).
- Recorded/licensed audio assets.
### Deferred — Future Versions
- installable PWA + offline caching (v1 is fully loadable offline if hosted as
  plain files, but a manifest/service worker is deferrable).
- More foods, garden/progression, day-night ambience (see IDEAS).
---
## 8. Non-Goals
- **No frameworks, no build tools, no bundlers** — the source tree is the shipped artifact.
- **No native apps / Electron** — the browser is the platform.
- **No monetization, ads, or telemetry** — it is a gift toy.
- **No realistic rabbit simulation** — charm over fidelity; behavior is scripted cuteness.
- **No manual/hand-drawn final art** — final assets must come from the tracked
  pipeline (`art/` ADRs) with provenance; placeholders are the exception and never ship.
---
## 9. Success Criteria
- [ ] Runs when opened/open-served statically on Chromium, Firefox, and Safari, desktop and iOS Safari / Android Chrome, with one code path.
- [ ] Feeding triggers the eating animation (≤ 100 ms perceived latency) and a noise.
- [ ] Petting triggers the happy/wiggle animation and a noise.
- [ ] No sound plays before a user gesture (autoplay-policy compliant).
- [ ] Page renders correctly at 390×844 and 1280×800 without horizontal scroll.
- [ ] Total transferred payload (HTML+CSS+JS+assets) < 5 MB.
- [ ] `prefers-reduced-motion` minimizes animation, without breaking interactions.
- [ ] Acceptance tests (Playwright smoke) pass locally before any commit believed "done".
